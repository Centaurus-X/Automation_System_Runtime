# Support

## Questions and ideas

Use GitHub Discussions for architecture questions, deployment planning, ideas
and general feedback. Do not post credentials, proprietary configurations or
plant details.

## Bugs

Open a bug report only after searching existing issues. Include the version,
profile, platform, sanitized configuration fragment, expected behavior, actual
behavior and a minimal lab reproduction.

## Security

Do not report vulnerabilities publicly. Follow `SECURITY.md` and use GitHub
private vulnerability reporting.

## Commercial engineering

Architecture review, integration, custom development, hardening, deployment
and validation may be available separately. See `COMMERCIAL_LICENSE.md`.

Community support is best effort and has no guaranteed response time.
